1 · arguments es un string

Texto que contiene JSON. Hay que hacer JSON.parse.

Y puede llegar truncado
Completo{"key":"height"}
Truncado{"key":"hei

Sin tokens de salida, o stream cortado. JSON.parse lanza. No lo «arregles» cerrando llaves.

07 · DIALECTO 3

Google Interactions · function_call

steps[ ] · paso

1 · Misma palabra, otra estructura

arguments es un objeto, no un string como en OpenAI.

2 · id obligatorio
id → call_id

Se devuelve en un paso function_result.

3 · requires_action

La interacción termina diciéndote «te toca a ti».

09 · POR QUÉ IMPORTA EL IDENTIFICADOR

Dos llamadas, la misma función

USUARIO

¿Cuánto mido y cuánto peso?

call_height → lookup_demo_value({ key: "height" }) → 170 cm
call_weight → lookup_demo_value({ key: "weight" }) → 70 kg
RESGUARDO

Mismo nombre de función en las dos. Sin el identificador, el proveedor no sabe cuál es la altura y cuál el peso.

12 · SSE · SERVER-SENT EVENTS

Una línea en blanco marca el final de un mensaje

Texto plano sobre HTTP. Esa marca es la única referencia fiable; el tamaño del trozo no dice nada.

  1. 1
    Acumular

    Cada trozo se añade a lo que quedó pendiente.

  2. 2
    Extraer mensajes completos

    Todos los que terminen en línea en blanco. El resto espera.

  3. 3
    Reconstruir cada llamada

    Cada mensaje añade su pieza a la llamada correcta.

  4. 4
    Revisar el final

    Si al cerrar queda texto inválido: error controlado. Nunca se adivina.

13 · FIXTURE REAL · GOOGLE INTERACTIONS

Anunciar, completar, cerrar

text/event-stream
event: step.start
data: {"event_type":"step.start", "index":0,
       "step":{"type":"function_call", "id":"google_call_0",
               "name":"read_field_value", "arguments":{}}}

event: step.delta
data: {"event_type":"step.delta", "index":0,
       "delta":{"type":"arguments_delta", "arguments":"{\"key\": \"Objetivo\"}"}}

event: step.stop
data: {"event_type":"step.stop", "index":0}
step.start anuncia la llamada con arguments vacío arguments_delta trae el JSON como texto step.stop cierra: solo ahí se hace JSON.parse Lo que une los tres eventos es index, no el id de la tool

15 · TRES REGLAS

Un parser correcto sabe qué hacer cuando no es perfecto

VARIAS PETICIONES No te quedes con la primera

Conserva todas, su orden y sus identificadores.

MENSAJE INCOMPLETO No adivines

{"key":"hei no es una llamada. Error controlado.

ERROR DEL PROVEEDOR Trátalo como error

Un evento error no puede parecer una respuesta vacía.

FRONTERA

El parser puede convertir argumentos inválidos en {} para no tirar el stream. Eso no autoriza a ejecutar: la capa de tools valida el esquema antes del handler.

El parser normaliza. La validación decide.

17 · LEDGER

Una acción con efectos no se reintenta a ciegas

Pseudocódigo del registro de llamadas ejecutadas.

pseudocódigo
const key = ledgerKey(call.name, call.args, occurrence);
if (ledger.has(key)) return ledger.get(key);   // ya se hizo
const result = await handler(call.args);
ledger.set(key, result);
La clave identifica esta llamada, con estos argumentos Si ya se completó, se devuelve el resultado guardado. No se escribe otra vez occurrence distingue «reintento de la misma llamada» de «dos llamadas iguales pedidas a propósito»
